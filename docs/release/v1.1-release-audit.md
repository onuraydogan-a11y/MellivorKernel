## v1.0 to v1.1 public API audit

Every v1.0 exported symbol remains exported. Existing public contracts are
unchanged except for behaviorally additive capabilities activated through new
objects or optional parameters. Additions are:

- `memory.SQLiteMemoryStore` — additive.
- `security.EnvSecretProvider`, `SecretNotFoundError`, `SecretValueError`, and
  `SecretConfigurationError` — additive; all errors derive from the existing
  `SecurityError` boundary and preserve registry fallback.
- `providers.gemini` adapter classes — additive optional module, deliberately

- `WorkflowEngine.__init__` gains optional keyword-only `max_concurrency` and
  `clock`; `WorkflowEngine.run` gains optional keyword-only `options=None`.
  All prior positional and keyword call patterns remain valid.

### Mandatory WorkflowStep compatibility re-check

The source at HEAD matches `v1.0.0` exactly. It remains a frozen, slotted
dataclass with fields in this exact order:

1. required `name: str`;
2. required `request: ExecutionRequest`;
3. `granted_permissions: frozenset[str] = frozenset()`;
4. `continue_on_failure: bool = False`.

Positional and keyword constructors, annotations, defaults, generated repr,
equality and hash participation, `dataclasses.fields()`, `dataclasses.asdict()`,
and ordinary subclass construction are unchanged. Strict MyPy accepts the
existing consumer expression `step.request.operation` without narrowing or
modification. ADR-0025 therefore repairs every breaking dimension introduced
by the original ADR-0024 implementation.

## Feature and cross-feature verification

- SQLite contract parity, persistence/reopen behavior, insertion-order
  determinism, overwrite/delete/clear semantics, corruption and storage error
  translation, lifecycle cleanup, parameterized SQL, and unchanged
  `InMemoryStore` behavior are covered and pass.
- Environment secrets distinguish missing, empty, and malformed requests;
  values are never present in exception text or provider state; registry
  fallback continues through the existing `SecurityError` contract.
- Gemini normalizes roles, system instructions, request parameters, responses,
  health checks, SDK/API/transport exceptions, and safety-filtered responses.
  Credentials are explicit configuration only and are excluded from errors.
  Claude and OpenAI suites remain green.
- Workflows preserve sequential behavior when options are absent. Resolvers
  execute through the normal `ExecutionEngine`; siblings receive the same
  pre-group context; results, failures, and raised exception groups are folded
  in declaration order; pending work is cancelled where possible after a
  stopping failure; `not_before` uses an injected clock and composes with
  resolvers and parallel groups. Executors are context-managed per group.
- Gemini works through the unchanged factory, registry, dispatcher, and engine
  seams. Environment providers work through the existing secret registry.
  SQLite lifecycle and shared components retain caller ownership.

### SQLite parallelism limitation

**Acceptable documented limitation, not a release blocker.** A single SQLite
connection uses `check_same_thread=True` and must not be shared across parallel
branches. This is an explicit component ownership constraint, not silent data
corruption or a workflow contract defect. Consumers can use separate store
instances, external synchronization, or a thread-safe backend. The memory
subsystem is not redesigned solely to remove this limitation.

## Dependency and CI audit

Base `dependencies` remains empty. Provider SDKs are optional and imported
only by their concrete adapter modules. Supported bounds are
`anthropic>=0.40,<1`, `openai>=1.0,<3`, and `google-genai>=2.0,<3`; Gemini also
owns `httpx>=0.28.1,<1`. `httpx` appears in `dev` because Gemini tests import
it directly; it is not an accidental mandatory runtime dependency.

The CI drift root cause was an accidental transitive test dependency. The
v1.0 CI environment installed provider SDKs whose then-resolved versions
transitively supplied HTTPX, while tests imported HTTPX directly without
declaring it in `dev`. Later unbounded provider-SDK major resolution migrated
toward HTTPX 2, so a clean environment could no longer satisfy that direct
test import compatibly. Commit `6b17370` permanently removes the transitive
assumption by declaring `httpx>=0.28.1,<1` in `dev` and directly in the
`gemini` runtime extra, and by bounding every supported provider SDK major
version. CI already installed the complete provider-extras set. GitHub Actions
run #41 at repaired HEAD `d24ade4` and run #42 at release commit `90840b5`
both completed successfully for Python 3.12 and 3.13.

## Security audit

- SQLite values and identifiers are passed with parameterized SQL; no query is
  built from caller data.
- Secrets and Gemini credentials do not enter logs, reprs, errors, or
  diagnostics. Raw vendor exceptions are translated at the adapter boundary.
- `RequestResolver` is a typed callable. There is no string/code evaluation.
- `ThreadPoolExecutor` is scoped by a context manager to one explicit parallel
  unit, with validated positive concurrency and no uncontrolled persistent
  threads.
- Scheduling performs one clock comparison per step and owns no sleep,
  polling loop, queue, daemon, persistence, or background runtime.
- No new global mutable state, hidden network call, insecure credential
  fallback, or import-time side effect was found. Provider calls occur only on
  explicit construction/invocation; tests inject fake clients.

## Upgrade guidance and known limitations

Upgrade with `pip install --upgrade mellivor-kernel==1.1.0`; existing v1.0
consumer code requires no source changes. Install provider integrations only
when required: `mellivor-kernel[anthropic]`, `[openai]`, or `[gemini]`.

Dynamic/parallel/scheduling behavior is opt-in per `WorkflowEngine.run` call.
Scheduling is not durable scheduling. One SQLite connection is not supported
across parallel branches. Gemini streaming, tool calling, multimodal input,
Vertex AI authentication, and batch execution remain deferred. No post-v1.1
development is included.
