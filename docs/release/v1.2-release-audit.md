## Scope

The release contains only Sprint 32 LocalProvider, ADR-0026, deterministic
protocol validation, integration through existing provider/execution seams,
the optional `local` dependency extra, and release-consistency documentation.
No Future Research capability or other feature is included.

## LocalProvider verification

LocalProvider requires an explicit endpoint and configured model, preserves
system/user/assistant text messages, selects that model, sends optional Bearer
authentication, honors the configured timeout, and retries timeout/transport
failures no more than `max_retries`. Authentication, HTTP, timeout,
connection, validation, and malformed-response failures translate into
`ProviderError` subclasses. Successful responses normalize text, model,
finish reason, and prompt/completion token counts.

Health checking is an explicit bounded one-token invocation. Import and
construction make no network request. There is no shell/subprocess execution,
model or runtime installation/download, process or server management,
background task, global executor, runtime discovery, or cloud fallback.
Credential values, authorization headers, response bodies, and raw transport
messages are absent from generated diagnostics.

Factory, registry, AI engine, and complete execution-engine paths are covered
by deterministic tests. Existing provider and v1.1 regression suites remain
unchanged and green.

## Protocol claim and trust boundary

The supported claim is: **LocalProvider supports caller-managed
OpenAI-compatible endpoints.** Tests validate the documented Chat Completions
protocol subset with injected HTTPX transports. Sprint 32 had no available
real Ollama, LM Studio, or vLLM runtime and did not download a model. This
release does not certify those runtimes or any model build; runtime-specific
differences require separate validation.

The caller is responsible for endpoint selection, trust, deployment, access
control, and runtime lifecycle. Configurable endpoints are a deployment trust
boundary, not an instruction for Kernel to implement an endpoint-security or
SSRF policy. Kernel validates URL shape, disables redirects and environment
proxy inheritance on its owned client, and sends only to the explicit URL.

## Dependency and packaging audit

Base runtime dependencies remain empty. Artifact metadata directly associates
`httpx>=0.28.1,<1` only with `local`, `gemini`, and development extras.
LocalProvider imports HTTPX directly and has no dependency on OpenAI SDK
internals or any Anthropic/OpenAI/Google SDK.

Existing supported bounds remain `anthropic>=0.40,<1`, `openai>=1.0,<3`, and
`google-genai>=2.0,<3`. The wheel metadata preserves these isolated extras,
requires Python 3.12 or later, and contains no unconditional `Requires-Dist`.
Wheel, sdist, clean base installation, and clean `[local]` installation pass.

## Upgrade guidance and known limitations

Upgrade with `pip install --upgrade mellivor-kernel==1.2.0`; no source change
is required. Install `mellivor-kernel[local]==1.2.0` only when using the new
adapter.

Kernel does not install/start runtimes, manage their processes, download
models, or own their lifecycle. The caller supplies and operates the endpoint.
Only the documented OpenAI-compatible protocol subset was validated;
runtime-specific interoperability and model-specific behavior were not
certified. All Future Research scope remains excluded.
