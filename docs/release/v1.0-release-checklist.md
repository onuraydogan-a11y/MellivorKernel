# Mellivor Kernel v1.0 Release Checklist

Status: Not ready for `1.0.0`.

This checklist records the release-readiness position of the current release
candidate (`v0.13.0`). It is an assessment of the responsibilities and
boundaries already defined by ADR-0002; it does not change the architecture
or schedule work by itself. `1.0.0` requires an explicit decision under
[ADR-0005](../adr/0005-versioning-strategy.md).

## Release gate

- [ ] All kernel responsibilities in [ADR-0002](../adr/0002-ai-enterprise-kernel-scope-and-subsystems.md) have stable, documented contracts.
- [ ] The public API and compatibility policy are approved for the `1.0.0` milestone.
- [ ] The release decision is recorded in an ADR or other approved release decision.
- [ ] The full test, lint, formatting, and strict type-checking gates pass for the release candidate.
- [ ] Documentation and examples describe the same supported behavior as the implementation.

## Responsibility assessment

| Responsibility | Current position | v1.0 disposition |
|---|---|---|
| AI orchestration | Implemented by `execution` as the orchestration layer across tools and providers. | [ ] Confirm the contract and integration behavior are stable. |
| Agent lifecycle | A minimal `agents` slice exists: one agent delegates to one workflow. Planning, reasoning, reflection, and multi-agent composition are not implemented. | [ ] Decide and document the required v1.0 agent scope. |
| Workflow engine | Sequential workflows are implemented through `WorkflowEngine` and `ExecutionEngine`. Dynamic steps, parallel execution, and scheduling are not implemented. | [ ] Confirm the supported workflow scope is sufficient for v1.0. |
| Memory abstraction | Text memory and an in-memory store are implemented. Persistence, embeddings, vector search, and RAG are not implemented. | [ ] Confirm the supported memory scope and storage contract. |
| Tool execution | Tool registration, permissions, and execution boundaries are implemented with demonstration tools. | [ ] Confirm the public tool contract and production boundary requirements. |
| Event bus | An in-process event bus and lifecycle events are implemented. | [ ] Confirm the event contract and whether distributed delivery is outside v1.0 scope. |
| Plugin loading | `plugins` remains an unimplemented package skeleton. | [ ] Design, implement, and validate plugin discovery, registration, and lifecycle, or explicitly resolve its v1.0 scope. |
| Multi-LLM provider abstraction | Provider interfaces are implemented, with `ClaudeProvider` as the current concrete provider. OpenAI, Gemini, and local-model integrations are not included. | [ ] Confirm provider coverage and the abstraction's compatibility guarantees. |
| Configuration | `KernelConfig`, environments, and configuration loading are implemented. | [ ] Confirm configuration and feature-flag behavior for release use. |
| Observability | Structured logging is implemented. Tracing, metrics, and audit trail remain unaddressed. | [ ] Define and implement the required v1.0 observability scope. |
| Security primitives | Authorization is implemented as a partial slice. Secrets management, encryption, and audit trail remain unaddressed. | [ ] Define placement and implement the required v1.0 security scope. |

## Current limitations

The current release candidate is not a `1.0.0` release because at least these
items remain unresolved:

- `plugins` has no implementation.
- The agent runtime is intentionally limited to one workflow and does not
  provide planning, reasoning, reflection, or multi-agent composition.
- Memory is text-only and in-memory; persistence, embeddings, vector search,
  and RAG are not provided.
- Workflow execution is sequential; dynamic steps, parallel execution, and
  scheduling are not provided.
- Only the Claude provider has a concrete implementation.
- Security primitives beyond authorization are not implemented.
- Observability beyond structured logging is not implemented.
- Bootstrap does not automatically compose the newer execution,
  authorization, workflow, and agent engines; consumers compose them
  explicitly.

These limitations are recorded here for release readiness only. Resolving
them requires the appropriate implementation, documentation, tests, and
architecture decisions where applicable; this checklist does not authorize
those changes.
