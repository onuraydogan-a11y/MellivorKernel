# Mellivor Kernel v1.0 Release Checklist

Status: Not ready for `1.0.0`. Scope is now locked — see
[ADR-0019](../adr/0019-release-readiness-and-scope-lock.md).

This checklist records the release-readiness position of the current release
candidate (`v0.13.0`). It is an assessment of the responsibilities and
boundaries already defined by ADR-0002; it does not change the architecture
or schedule work by itself. `1.0.0` requires an explicit decision under
[ADR-0005](../adr/0005-versioning-strategy.md). As of Sprint 24,
[ADR-0019](../adr/0019-release-readiness-and-scope-lock.md) is that
decision's scope-defining precursor: it classifies every ADR-0002
responsibility as `Included in v1.0`, `Deferred to v1.1`, or `Future
research`, so this checklist's remaining open items are now closing
actions against a fixed target rather than open-ended questions.
Declaring `1.0.0` itself remains a separate, later decision, made once
every `Included in v1.0` closing action below is complete.

## Current limitations, by classification

Per [ADR-0019](../adr/0019-release-readiness-and-scope-lock.md). These are
recorded for release readiness only; resolving any `Deferred to v1.1` or
`Future research` item requires its own implementation, documentation,
tests, and architecture decisions where applicable — this checklist does
not authorize those changes.

**Deferred to v1.1** — real, scoped, schedulable directly once `1.0.0`
ships, no further design gate needed:

- Workflow: dynamic steps (a step's request built from an earlier step's
  result), parallel execution, scheduling.
- Memory: a second, persistent `MemoryStore` implementation.
- Providers: additional concrete providers (Gemini, local models).
- Security: a concrete `SecretProvider` backend.

**Future research** — open-ended, no committed design or timeline, in
several cases an open question of whether the capability belongs in the
kernel at all versus a consuming product:

- Agent lifecycle: planning, reasoning, reflection, multi-agent
  composition.
- Memory: embeddings, vector search, RAG.
- Event bus: distributed delivery (Kafka/NATS/Redis-backed).
- Plugin loading: marketplace, remote plugins, sandboxing, hot reload,
  signature verification, package installation.
- Observability: a concrete metrics/tracing vendor integration.
- Security: authentication, OAuth, SSO, RBAC, encryption-at-rest.

**Structural note, unaffected by this scope lock:**

- `bootstrap` itself still does not automatically compose the newer
  execution, authorization, workflow, and agent engines — but as of
  Sprint 22, `ai_engine.AIEngineBuilder` provides a concrete, supported
  composition mechanism on top of a bootstrapped `RuntimeContext`, so
  consumers no longer need to hand-wire that chain themselves.
